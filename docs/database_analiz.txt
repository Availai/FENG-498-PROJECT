1. GENEL MİMARİ ÖZETİ
--------------------------------------------------------------------------------
Tarlam, "offline-first" prensibiyle çalışır. Kullanıcının cihazında birincil
depolama Drift (SQLite) üzerinden yapılır; ağ erişimi olduğunda bir outbox
(SyncJobs) tablosu üzerinden backend PostgreSQL/PostGIS'e LWW (Last Write Wins)
stratejisiyle senkronize edilir. Bitki bilgi tabanı (292 Türk bitkisi), build
zamanında JSON'dan SQLite asset'e dönüştürülerek uygulamaya gömülür. Auth
sorumluluğu Firebase Auth'taydı; Firestore kullanılmıyor.

Kısa veri akışı:
  seed_plants.json  ──(build script)──►  turkish_crops.sqlite (asset, read-only)
                                                 │
                                                 ▼
                                        TurkishCropsRepository (picker/skorlama)
                                                 │
  UI ──► Drift (smart_agri_local.sqlite) ──► SyncJobs outbox
                    ▲        │                       │
                    │        │                       ▼
                    │        │             /api/sync/push & /pull
                    │        │                       │
           Hive caches       │                       ▼
        (sensor, fuel,       │            PostgreSQL + PostGIS (backend)
         plant_cache ...)    │                       │
                             ▼                       ▼
                     Firebase Auth UID ◄──── farmers.firebase_uid
                    (Fields.farmerUid FK)


2. KATMANLARIN LİSTESİ
--------------------------------------------------------------------------------
 (A) Drift / SQLite  — Birincil yerel uygulama verisi
 (B) Turkish Crops SQLite (asset)  — Salt-okunur bitki bilgi tabanı
 (C) Hive  — KV cache + eski veri aynaları
 (D) verified_agri_database.dart  — Legacy in-memory bitki listesi
 (E) Backend PostgreSQL/PostGIS  — Sunucu tarafı kalıcı depo
 (F) Firebase Auth  — Kullanıcı kimliği (sadece UID)
 (G) seed_plants.json + build_turkish_crops_db.py  — Build pipeline
 (H) WorkManager  — Arka planda senkron zamanlayıcı (storage değil ama veri
     hareketini tetikler)


================================================================================
(A) DRIFT (SQLite)  — BİRİNCİL YEREL DEPO
================================================================================

AMAÇ
  Kullanıcının tarla/ürün/takvim/sulama/rapor/sync verilerinin offline-first
  tutulduğu ana veritabanı. Tüm ekranlar önce buraya yazar, sonra backend'e
  push edilir.

DOSYALAR
  - lib/data/app_database.dart           (şema + tablolar, schemaVersion: 3)
  - lib/data/app_database.g.dart         (build_runner çıktısı)
  - lib/services/local_data_repository.dart     (üst seviye CRUD + Hive migrate)
  - lib/services/repositories/sync_repository.dart  (SyncJobs/SyncState DAO)
  - lib/services/repositories/field_repository.dart
  - lib/services/repositories/calendar_repository.dart

FİZİKSEL KONUM
  ${getApplicationDocumentsDirectory()}/smart_agri_local.sqlite
  (açılamazsa system tmp'e fallback)

TABLOLAR
  1) Fields            — Tarla kaydı
       id(TEXT PK), farmerUid(TEXT nullable), name, crop, latitude, longitude,
       polygonJson, createdAt, updatedAt, deletedAt
  2) FieldCrops        — Bir tarlaya ekilen bitki(ler) / alt bölgeler
       id(TEXT PK), fieldId FK→Fields, name, zoneStart, zoneEnd,
       rowSpacingCm, plantSpacingCm, zonePolygonJson
  3) CalendarEvents    — Tarla/ürün olayları (ekim, sulama, hasat vb.)
       id, fieldId nullable FK, cropId nullable FK, eventType, eventDate,
       source(manual/auto), metadataJson
  4) IrrigationPlans   — Sulama önerileri
       id, fieldId FK, cropId nullable FK, scheduledDate, shouldIrrigate,
       reason, recommendation
  5) SuitabilityReports — Bitki uygunluk rapor arşivi
       id, fieldId FK, cropName, score, reportJson
  6) SyncJobs          — Outbox (backend'e gönderilmeyi bekleyen değişiklikler)
       id(AI), entityType, entityId, operation, payloadJson, status
       (pending/in_progress/failed), attemptCount, lastError
  7) SyncState         — Senkron imleçleri
       key(PK), value, updatedAt   (anahtarlar: last_push_at, last_pull_at)

MIGRATION'LAR
  v1 → v2 : FieldCrops.zonePolygonJson eklendi
  v2 → v3 : Fields.farmerUid eklendi (Firebase UID bağlanması için)
  Hatalar sessizce yutulur; schema migration başarısızlığı uygulamayı
  düşürmez (offline-first dayanıklılığı için).

İLİŞKİLER
  - Fields.farmerUid  ◄──►  Firebase Auth UID
  - FieldCrops.fieldId ──►  Fields.id (aynı kullanıcıya ait tarla)
  - SyncJobs kayıtları ──►  /api/sync/push (backend Postgres)
  - Hive (user_crops)  ──►  Fields + FieldCrops (tek seferlik migrate)

(B) TURKISH CROPS SQLite  — SALT-OKUNUR BİTKİ BİLGİ TABANI (292 BİTKİ)
================================================================================

AMAÇ
  Kullanıcı bitki seçerken veya uygunluk puanı hesaplanırken okunan statik
  referans veritabanı. Build zamanında üretilip asset olarak gömülür.

DOSYALAR / KONUMLAR
  Source   : backend/data_pipeline/seed_plants.json
  Builder  : backend/data_pipeline/build_turkish_crops_db.py
  Output   : backend/data_pipeline/output/turkish_crops.sqlite
  Asset    : assets/data/turkish_crops.sqlite        (pubspec'te kayıtlı)
  Runtime  : ${getApplicationDocumentsDirectory()}/turkish_crops.sqlite
             (ilk açılışta asset buraya kopyalanır)
  Repo     : lib/data/turkish_crops_repository.dart  (singleton)

TABLO ŞEMASI (crops)
  id, name_tr, aliases(JSON), scientific_name, category,
  sowing_months(JSON), harvest_months(JSON),
  temp_min_c, temp_max_c, optimal_temp_c,
  water_need, sun_need, soil_ph_min, soil_ph_max,
  soil_type, region_suitability(JSON), fertilizer_notes,
  common_pests(JSON), diseases(JSON), growing_tips, days_to_harvest,
  search_key  (ASCII normalize edilmiş Türkçe arama anahtarı)

  İndeksler: idx_crops_search(search_key), idx_crops_category, idx_crops_name

REPOSITORY API (TurkishCropsRepository.instance)
  ensureReady()              – asset'i cihaza kopyala, DB aç
  search(query, category?, limit=80)
  findByName(name)           – Türkçe normalize ederek eşleştirme
  byId(id)
  listCategories()
  popular(limit=12)          – Hardcoded öncelikli bitki listesi
  TurkishCrop.scoreFor({temperature, soilPh, weeklyRain, month, region})
     -> SuitabilityScore(score, reasons)

KULLANIM NOKTALARI
  - lib/screens/field_detail_screen.dart      (bitki picker + skorlama)
  - lib/screens/field_3d_planner_screen.dart  (292'lik picker)
  - lib/screens/turkish_crops_search_screen.dart (pickerMode=true ile seç/dön)

İLİŞKİLER
  - seed_plants.json  ──(build script)──►  turkish_crops.sqlite
  - TurkishCrop       ──(seçim)──►  FieldCrops.name / Fields.crop (Drift)
  - TurkishCrop.scoreFor  ──► SuitabilityReports.reportJson

(G) SEED_PLANTS.JSON + BUILD SCRIPT  (DATA PIPELINE)
================================================================================

AMAÇ
  Bitki bilgi tabanını tek kaynaktan (JSON) sürdürmek; build aşamasında
  SQLite asset'ine dönüştürmek.

DOSYALAR
  backend/data_pipeline/seed_plants.json           (292 kayıt, editable)
  backend/data_pipeline/build_turkish_crops_db.py  (dönüştürücü)
  Çıktı:
    backend/data_pipeline/output/turkish_crops.sqlite
    → manuel veya script ile assets/data/turkish_crops.sqlite'a kopyalanır

PROCESS
  1. JSON oku
  2. name_tr + aliases → normalize('ı→i', 'ğ→g', ...) = search_key
  3. Liste alanlarını JSON string'e encode et
  4. SQLite CREATE + INSERT
  5. İndeksleri oluştur
  6. Asset klasörüne kopyala (shutil.copy2)

İLİŞKİLER
  JSON  ──►  SQLite asset  ──►  TurkishCropsRepository
  Yeni bitki eklemek için: /add-crop skill'i (seed + rebuild tek komutta)


================================================================================
(H) WORKMANAGER  — ARKA PLAN SYNC
================================================================================

AMAÇ
  Kullanıcı uygulamada değilken de senkron ve hava uyarılarının çalışması.
  Android-only.

PERİYODİK GÖREVLER
  periodicWeatherCheck  ~3 saat  – Tarla koordinatından hava uyarısı
  periodicSyncFlush     ~1 saat  – Outbox push cycle

DOSYALAR
  lib/services/background_sync_service.dart
  lib/services/sync_service.dart

AKIŞ (sync_service.dart, runForegroundSync)
  1) Network kontrolü (DNS lookup)
  2) failed job'ları pending'e çevir (retry)
  3) Push cycle: SyncJobs pending → /api/sync/push → completed/failed
  4) Pull cycle: /api/sync/pull?since=last_pull_at → LWW uygula
  5) SyncState['last_push_at' | 'last_pull_at'] güncelle

3. UÇTAN UCA VERİ AKIŞ SENARYOLARI
================================================================================

Senaryo 1 — YENİ TARLA + BİTKİ EKLEME
  1) Kullanıcı field_detail_screen'de bitki picker açar.
  2) TurkishCropsRepository.search() → turkish_crops.sqlite (asset).
  3) Seçilen TurkishCrop → FieldCrops satırı olarak Drift'e insert.
  4) Aynı transaction'da SyncJobs'a 'field_crop_upsert' payload'ı eklenir.
  5) Foreground/WorkManager sync tetiklenince /api/sync/push gönderir.
  6) Backend Postgres'e farmers.firebase_uid → fields → field_plants upsert.

Senaryo 2 — UYGUNLUK RAPORU
  1) WeatherRepository (OpenWeather/MGM) → sıcaklık, yağış.
  2) SoilGrids / kullanıcı girişi → pH.
  3) TurkishCrop.scoreFor(...) → SuitabilityScore.
  4) Sonuç SuitabilityReports tablosuna (Drift) kaydedilir; UI'da gösterilir.
  5) Arka planda outbox üzerinden backend'e push edilir.

Senaryo 3 — İLK KURULUM / LEGACY MIGRATION
  1) App ilk kez açıldığında Hive box'ları açılır.
  2) settingsBox['drift_legacy_hive_migrated_v2'] == false ise:
     user_crops (Hive) → Fields + FieldCrops (Drift) transfer edilir,
     flag true yapılır.
  3) turkish_crops.sqlite asset'i Documents klasörüne kopyalanır
     (yoksa veya asset'in sürümü daha yeni ise).
